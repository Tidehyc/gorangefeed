# GoRangeFeed 需求规格说明书

> 本文档定义 GoRangeFeed 系统的业务边界、角色场景、功能需求（FR）与非功能需求（NFR），作为系统设计与验收的基准。

---

## 一、项目定位与目标

### 1.1 系统定位
个人独立设计实现的短视频 Feed 流后端系统，覆盖「发布 → 分发 → 消费 → 互动 → 通知」全链路。

### 1.2 边界与范围
- **包含**：单体 API + 独立 Worker 架构、本地一键启动（Docker Compose）、完整链路 E2E 自动化验收、全场景流（全局最新流、关注流、60分钟滑动窗口热门流、多路召回轻量推荐流）、关键热点链路压测。
- **排除**：深度学习超重型模型训练精排（一期采用滑动热度衰减+多路召回打散）、视频服务端转码与自动抽帧、后台管理独立 UI、私信系统、收藏夹（规划至二期进阶演进）。

### 1.3 验收标准
1. **本地快速启动**：新环境 10 分钟内通过 Docker Compose 启动全套依赖并跑通 `scripts/e2e.sh`。
2. **性能与指标可观测**：热点链路达到设计性能指标，关键链路具备指标埋点、Prometheus `/metrics` 监控与健康探针。
3. **测试覆盖**：所有 P0/P1 功能需求均配备自动化单元/集成测试。
4. **前端无缝接入**：后续补充前端时直接消费现有接口与媒体静态路由（含 HTTP 206 Range 支持），无需调整后端接口契约。

## 二、角色与核心场景

### 2.1 用户角色

| 角色 | 权限与能力 | 说明 |
|---|---|---|
| **游客** | 浏览全局最新 Feed、热门/推荐 Feed、查看视频详情与评论 | 未登录，只读访问 |
| **登录用户** | 游客权限 + 发布视频、点赞/取消、评论、关注/取关、接收通知、已赞列表 | 一期所有认证用户具备同等权限 |
| **运营/管理员** | 违规内容强制下架 | 一期通过受信管理接口与数据库运维手段处理 |

### 2.2 核心业务场景
1. **浏览与冷启动（游客/新用户）**
   - 游客与登录用户均可即刻刷到全局最新流与推荐/热门流（软鉴权兼容模式，未登录返回兜底流，已登录自动注入点赞/关注态）。
   - 用户播放视频，端侧自动上报曝光与播放时长，驱动播放量自增与已看去重。
2. **内容创作与分发（创作者）**
   - 登录创作者上传视频文件，填写标题/封面后点击发布。
   - 发布成功后，视频即刻进入作者作品列表；并通过 Outbox 事件驱动写入全局时间线与关注流分发（一期 M2 交付单文件上传与发布；分片续传在 M2.5 交付）。
3. **异步互动、热榜派生与弱网通知**
   - 用户 A 点赞用户 B 的视频，用户 B 在线时通过 SSE 低延迟收到通知提示；同时触发 Redis 滑动分钟桶热度分自增。
   - 用户 B 离线后再上线，通过历史补拉接口完整拉取期间所有未读通知，确保通知不重不漏。

## 三、功能需求清单（FR）

> 优先级约定：
> - **P0**：所属批次核心交付项，验收硬性依赖。
> - **P1**：所属批次应交付项，资源受限时可顺延。
> - **P2**：锦上添花项，不阻塞批次交付。

### 3.1 账号域（Account - M1）

| 编号 | 功能需求 | 阶段 | 优先级 | 验收标准 |
|---|---|---|---|---|
| **FR-ACC-01** | 用户名密码注册 | M1 | P0 | 用户名重复返回 `conflict`；密码强度不足返回 `invalid_param`；成功返回用户 ID |
| **FR-ACC-02** | 登录认证 | M1 | P0 | 凭证校验错误返回 `unauthorized`；成功签发 Access + Refresh Token 及对应有效时长 |
| **FR-ACC-03** | Token 轮转与刷新 | M1 | P0 | 每次用 Refresh 换新 Access 时轮转 Refresh Token；重放旧 Refresh 立即撤销该会话并返回 `unauthorized` |
| **FR-ACC-04** | 登出当前会话 | M1 | P0 | 登出后对应 Access 与 Refresh Token 均置为失效状态 |
| **FR-ACC-05** | 用户资料维护 | M1 | P1 | 支持查询与更新昵称及简介，更新后即刻生效 |
| **FR-ACC-06** | 头像上传 | M1 | P2 | 仅支持 jpg/png/webp 格式且大小 ≤10MB；非法文件类型返回 `invalid_param` |

### 3.2 视频与播放域（Video & Playback - M2 / M2.5 / M3）

| 编号 | 功能需求 | 阶段 | 优先级 | 验收标准 |
|---|---|---|---|---|
| **FR-VID-01** | 单文件上传 | M2 | P0 | 限制 MP4 格式且大小 ≤200MB；超限返回 `invalid_param`；存储路径安全隔离无穿越风险 |
| **FR-VID-02** | 视频发布 | M2 | P0 | 填写标题/封面提交后插入 `videos` 行置为 `published`；返回视频 ID |
| **FR-VID-03** | 视频详情查看 | M2 | P0 | 返回作者信息、互动统计数及当前用户点赞态；已下架内容返回 `not_found` |
| **FR-VID-04** | 作者作品列表 | M2 | P1 | 仅包含 `published` 状态视频；支持按发布时间倒序与游标分页 |
| **FR-VID-05** | 下架视频 | M2 | P1 | 非作者本人操作返回 `forbidden`；下架后从 Feed 流与公开详情中隐藏 |
| **FR-VID-06** | 分片上传与断点续传 | M2.5 | P0 | 200MB 文件模拟网络中断 3 次后仍能续传成功；分片落盘无重复与丢失 |
| **FR-VID-07** | 同文件秒传 | M2.5 | P1 | 相同文件 SHA256 哈希匹配时，二次上传响应耗时 < 300ms |
| **FR-VID-08** | 播放与曝光行为上报 | M3 | P0 | 支持客户端上报曝光与播放（`play` / `complete` / `watch_ms`）；触发 `video_stats.view_count` 原子自增；写入近期用户曝光集合用于推荐去重 |

### 3.3 互动域（Interaction - M4）

| 编号 | 功能需求 | 阶段 | 优先级 | 验收标准 |
|---|---|---|---|---|
| **FR-INT-01** | 点赞视频 | M4 | P0 | 重复点赞保持幂等；`video_stats.like_count` 计数与实际点赞行数一致 |
| **FR-INT-02** | 取消点赞 | M4 | P0 | 未点赞时取消操作幂等返回成功；点赞计数不为负 |
| **FR-INT-03** | 发表评论 | M4 | P1 | 支持一级评论与基于 `parent_id` 的单层回复；文本长度超限拦截；**支持客户端 `idempotency_key` 幂等防重放** |
| **FR-INT-04** | 评论列表 | M4 | P1 | 支持游标分页；已删除评论不展示 |
| **FR-INT-05** | 删除评论 | M4 | P1 | 仅允许作者删除；删除后统计数同步递减 |
| **FR-INT-06** | 用户已赞视频列表 | M4 | P1 | 支持查询当前用户点赞过的视频列表，按点赞时间倒序游标分页 |
| **FR-INT-07** | 评论点赞与热评排序 | M4 | P2 | 支持对评论点赞/取消；评论列表支持按点赞数倒序排序与时间倒序切换 |

### 3.4 关系域（Relation - M4）

| 编号 | 功能需求 | 阶段 | 优先级 | 验收标准 |
|---|---|---|---|---|
| **FR-REL-01** | 关注用户 | M4 | P0 | 重复关注保持幂等；禁止关注自身（返回 `invalid_param`） |
| **FR-REL-02** | 取消关注 | M4 | P0 | 取关幂等处理，返回成功 |
| **FR-REL-03** | 关注/粉丝列表 | M4 | P1 | 支持按时间倒序游标分页查询 |
| **FR-REL-04** | 关注与粉丝数统计 | M4 | P1 | 计数值与 `follows` 关系行数一致 |
| **FR-REL-05** | 互粉好友状态判定 | M4 | P1 | 接口支持返回与目标用户的关注关系（未关注、已关注、互粉好友 `is_friend=true`） |

### 3.5 Feed 场景流（Feed - M3 / M4 / M4.5）

| 编号 | 功能需求 | 阶段 | 优先级 | 验收标准 |
|---|---|---|---|---|
| **FR-FEED-01** | 全局最新流（`scene=global`） | M3 | P0 | 游标分页翻页无重复、无遗漏；Redis 异常时自动降级回源 DB 且结果一致 |
| **FR-FEED-02** | 关注流（`scene=following`） | M4 | P0 | 仅展示已关注作者的发布视频；**基于普通作者写扩散（推入粉丝 Inbox）与大 V 作者读扩散（读取作者 Outbox）推拉结合模式分发**；取关后不再出现 |
| **FR-FEED-03** | 软鉴权浏览 | M3 | P1 | 匿名请求返回全局兜底流；登录请求自动解析用户上下文并注入点赞/关注态 |
| **FR-FEED-04** | 已下架内容过滤与补齐 | M3 | P0 | 遇下架内容自动后移补齐至 `limit` 数量，游标指针正确推进至最后扫描项 |
| **FR-FEED-05** | 60分钟滑动窗口热门流（`scene=hot`） | M4.5 | P0 | 基于 Redis 分钟桶热度打分衰减机制；采用 `as_of + offset` 稳定快照游标分页，保证动态变分下翻页不漏刷、不重复 |
| **FR-FEED-06** | 轻量多路召回推荐流（`scene=recommend`） | M4.5 | P0 | 50% 热门池 + 30% 最新池 + 20% 探索池组合召回；结合 M3 曝光历史剔除近期已看；单页同一作者强制打散间隔 |
| **FR-FEED-07** | 历史累计高赞榜单（点赞榜） | M4 | P1 | 支持按历史累计点赞数 `like_count DESC, id DESC` 复合游标分页展示爆款视频 |

| 编号 | 功能需求 | 阶段 | 优先级 | 验收标准 |
|---|---|---|---|---|
| **FR-NOT-01** | 事件驱动通知产生 | M5 | P0 | 点赞/评论/关注异步落库产生通知；自身操作不通知自身；P99 < 1s |
| **FR-NOT-02** | 通知列表查询 | M5 | P0 | 游标分页，按时间倒序排列 |
| **FR-NOT-03** | 未读通知计数 | M5 | P0 | 计数值严格对齐 `is_read=false` 记录总数 |
| **FR-NOT-04** | 标记已读 | M5 | P1 | 支持单条与批量一键已读 |
| **FR-NOT-05** | 单实例 SSE 推送 | M5 | P0 | 在线事件推送端到端延迟 < 100ms；支持基于 `Last-Event-ID` 断线补拉 |
| **FR-NOT-06** | 跨实例 SSE 广播 | M5.5 | P2 | 基于 Redis Pub/Sub 广播实现多实例下跨节点推送，网络波动靠重连补拉 |
| **FR-NOT-07** | 评论 `@提及` 用户通知 | M5 | P1 | 评论解析 `@username` 异步触发提及通知，离线可补拉，在线走 SSE 实时到达 |

## 四、非功能需求（NFR）

### 4.1 性能要求（PERF）
- **NFR-PERF-01**（Feed 首页）：10,000 视频规模、1,000 并发连接下，首页请求 P99 < 80ms，缓存命中率 > 95%。
- **NFR-PERF-02**（Feed 冷区）：翻页至 72h 外冷数据时，P99 < 200ms。
- **NFR-PERF-03**（点赞并发）：单视频 300 并发点赞下，P99 < 120ms，计数零丢失。
- **NFR-PERF-04**（大文件续传）：200MB 文件断网 3 次重试后能完整合并，无分片重复落盘。

### 4.2 可靠性要求（REL）
- **NFR-REL-01**（明确持久化）：写接口返回 2xx 代表数据已在 MySQL 完成事务落库，不存在模糊挂起态。
- **NFR-REL-02**（最终一致性）：派生通知通过 Outbox 保证最终一致（P99 < 1s）；实时 SSE 允许重连补拉。
- **NFR-REL-03**（Outbox 容灾）：实例异常崩溃后，已持有的租约超时自动释放并可被接管调度。
- **NFR-REL-04**（消费幂等）：消费端通过 MySQL `consumed_events` 表与天然幂等的 Redis 操作防御重复消费。
- **NFR-REL-05**（平滑降级）：Redis 不可用时透明回源 DB，功能保持可用但可容忍延迟上升。

### 4.3 安全要求（SEC）
- **NFR-SEC-01**：密码采用 bcrypt 散列（cost ≥ 10），严禁存储明文。
- **NFR-SEC-02**：服务端仅存储 Refresh Token 的哈希值，防止凭证泄露。
- **NFR-SEC-03**：长期认证 Token 不在 URL Query 暴露；Web SSE 连接使用单次短期 Ticket。
- **NFR-SEC-04**：文件上传校验魔数（Magic Number）与后缀，存储路径严格哈希化规避路径穿越。
- **NFR-SEC-05**：鉴权组件异常时采取“安全失败（Fail-Closed）”原则直接拒绝请求。
- **NFR-SEC-06**：日志输出自动脱敏，禁止记录密码、Token 等敏感信息。
- **NFR-SEC-07**（接口限流）：基于 Redis 滑动窗口对登录注册（IP 维度）及点赞、评论、关注（UID 维度）进行频控保护，超限返回 `rate_limited`。

### 4.4 可观测性（OBS）
- **NFR-OBS-01**：提供轻量健康探针 `/healthz`（进程存活）、就绪探针 `/readyz`（依赖健康）以及标准 Prometheus 指标端点 `/metrics`。
- **NFR-OBS-02**：全链路统一注入 `request_id`，请求日志结构化输出并沿响应头透传。
- **NFR-OBS-03**：Prometheus 核心指标埋点：API 耗时分位直方图、HTTP 状态码计数、Feed 缓存命中/回源率、慢查询、Outbox 积压与重试。

### 4.5 可维护性与扩展性（MAINT & EXT）
- **NFR-MAINT-01**：数据库迁移脚本版本化管理，历史迁移文件在 CI 中强校验不可变性。
- **NFR-MAINT-02**：配置加载实行全量启动校验，发现错误一次性汇总输出。
- **NFR-EXT-01**：资源访问标准化：视频、封面、头像均通过服务端 HTTP 路由（如 `/media/...`）或预签名 URL 访问，API 响应不暴露服务器本地路径；**视频媒体路由原生支持 HTTP 206 Partial Content（Range 请求），保障浏览器端拖拽流式播放**。
- **NFR-EXT-02**：统一同源反代部署，前端静态资源与 `/api` 挂在同源入口，减少跨域复杂度。

## 五、核心术语表

| 术语 | 定义与业务含义 |
|---|---|
| **权威事实（Fact）** | 必须由主业务事务同步落库的数据（如点赞/关注关系、视频元数据、评论及计数）。 |
| **持久投影（Projection）** | 由事件驱动异步消费计算得到的数据（如系统通知、热榜分值、分发时间线）。 |
| **可丢提示（Ephemeral Alert）**| 仅用于在线低延迟通知的通道推送（如 SSE），依托客户端补拉兜底。 |
| **时间线 Floor** | 滑动窗口内最小的单调视频 ID，作为 Redis 内存索引与 DB 冷区分界线。 |
| **单调游标（Cursor）** | 服务端发放的分页位置标记，本系统采用严格递增的视频 ID 保证翻页不漏项。 |
| **推拉结合（Hybrid Fanout）** | 普通创作者发布时写粉丝 Inbox（推），大 V 创作者发布时写作者 Outbox、读端拉取（拉），平衡读写放大。 |
